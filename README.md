# 小洛的身体监控

在 WebUI 里点身体部位，角色会像被碰到一样回复；插件同时记录并更新每个部位的身体状态。

> 版本 1.1.1。内部插件名是 `astrbot_plugin_body_monitor`（旧版叫 `astrbot_plugin_interact_touch`，设置文件会沿用），显示名称是「小洛的身体监控」。

## 安装

- 把 `小洛的身体监控_v1.1.1.zip` 上传到 AstrBot 插件管理，或解压到 `data/plugins/` 下
- 在插件配置里填好「互动回复目标会话（UMO）」，或者先让机器人收到一条消息
- 打开插件页即可使用；首次使用会自动生成 `positions.json` 和默认身体状态

## 功能一览

- WebUI 身体图：点热区触发角色回复，支持连击、冷却、多部位合并
- 热区编辑：拖动、缩放、椭圆/胶囊/多边形、父子分组、复制、水平翻转
- 多预设：新建/切换/删除/导入/导出，每个预设可以有独立底图
- 身体状态：每个部位温度、状态、倒计时、严重度，互动后自动评估全身
- 角色工具：`get_body_state`，角色可以主动查看自己身体
- 更新方式：互动后、提到部位、按轮数、手动按钮；任意一次更新都会重置轮数计数
- 互动词库：名词/形容词/动词按钮，自由新增、删除、切换，实时预览组合
- 日志：互动与状态更新记录，只保存在内存

## 怎么用

1. 在 AstrBot 插件配置里填好「互动回复目标会话（UMO）」，或者先让机器人收到一条消息，插件会自动记住最近会话。
2. 打开插件页面，点身体部位即可。
3. 角色回复会走 AstrBot 的正常对话流水线，人格、上下文、记忆都由流水线处理。
4. 回复模型由 AstrBot 自己的配置/会话选择，插件不单独设置；只有状态更新模型可以在插件配置里单独选。

## 连击

- 在「连击」时间内连续点同一个部位，会累加次数，停手后才结算成一次互动
- 多个部位一起点会合并成一次互动，例如「2次左手、3次右手」
- 连击时间填 0 就关闭连击，每次点击立即结算
- 连击时间可以在插件配置里改，也可以直接在右侧「互动触碰」独立列里改

## 互动触碰

右侧的「互动触碰」是一个大按钮，点开后会在右侧面板左边弹出独立列，右上角有「关闭」。

独立列固定分成三块，每一块都是同一类词：

- **名词**
- **形容词**
- **动词**

每块右上角固定一个 **＋**，不会跟着词跑；词横向排列，摆不下自动换行。点词切换当前选择（标红），每个词右侧的小 **×** 删除，每类至少保留一个。

- 点 **＋** 出现输入框，输入后按回车或点别处新增并选中，Esc 取消
- 连击和当前组合预览也都在独立列里
- 大按钮上会显示当前组合，比如「用手指轻轻的戳」
- 选项和当前选择保存在 `settings.json`，重启保留

例如加「用力的」形容词并选中，组合变成「用手指用力的戳」；再加「捏」并选中，就变成「用手指用力的捏」。

## 视图

- 滚轮缩放（0.25×–8×）
- 按住右键或中键拖动平移
- 「重置视图」回到适应窗口的初始大小

## 日志

- 右下角显示最近的互动记录：成功绿色，冷却/失败红色
- 一次状态更新只显示一条，例如：`状态更新: 正面右大腿、正面左大腿、胸口、左脸、右脸`
- 日志只保存在内存里，重启或重载插件会清空

## 身体状态

- 左侧是「身体状态」列表，每个部位显示温度，行右侧显示简要状态
- 点部位后，状态会直接展开在这个部位下面，像展开子级一样：
  - 温度
  - 每条状态和剩余秒数
  - 状态按严重度标绿 / 黄 / 红
- 每条状态都有倒计时，时间到自动消失，UI 同步删除
- 倒计时没结束又被互动时，AI 会把状态叠加/加重（有点痒 → 痒 → 很痒），并重新评估持续时间
- 每次状态更新都会评估全身，考虑连带反应（比如大腿被戳 → 大腿发痒、心跳加快、左右脸发烫）
- 左侧有「重置状态」和「更新状态」按钮：
  - 重置：清空当前预设的全部状态，所有部位回到体温基线
  - 更新：主动让 AI 根据最近对话重新评估一次全身状态
- 状态按预设分开保存，切换预设会切换对应的身体状态

### 角色怎么查看状态

插件注册了一个工具 `get_body_state`。角色想知道自己身体怎么样时，可以自己调用：

- 不带参数：返回全身有状态的部位
- 带部位名：返回指定部位的温度、状态和剩余时间

配置里的「允许角色查看身体状态工具」可以关掉这个工具。需要模型支持工具调用（function calling）。

### 状态相关配置

- 身体状态更新总开关
- 允许角色查看身体状态工具
- 状态更新使用的模型（留空即跟随回复模型；下拉列表直接来自 AstrBot 的模型配置，可以单独选更快的模型）
- 状态更新提示词（支持 `{time}`、`{states}`、`{action}`、`{reply}`、`{history}`、`{focus}`、`{min_duration}`、`{max_duration}`、`{max_notes}`、`{baseline}` 占位符）
- 互动后更新全身状态
- 聊天提到身体部位时更新状态
- 按会话轮数定时更新状态
- 每多少轮对话更新一次状态：填 **1** 就是每轮正常聊天后都更新；默认 **3** 轮
- 状态更新参考最近多少轮对话（定时/提到部位/手动时使用；互动本身用当次回复）

右侧「状态参数」里点「设置」会打开独立的「状态设置」列，可以设置：

- 体温基线（默认 36.5°C）
- 最短 / 最长持续时间（默认 5 秒 / 604800 秒）
- 每个部位最多几条状态（默认 6）
- 取消会恢复打开前的值，完成会保存

### 状态更新为什么会快慢不一

每次更新是**回复之后的第二次模型调用**：

1. 点热区 → 走 AstrBot 流水线生成回复（用 AstrBot 的模型）
2. 回复完成后，插件再调用「状态更新使用的模型」，把全身部位和回复一起给它
3. 模型返回 JSON 后写入状态，页面轮询刷新

所以总耗时 = 回复生成时间 + 状态更新模型时间。之前状态更新默认跟回复用同一个模型，回复模型慢时状态也会慢。现在可以单独给状态更新选更快的模型；页面刷新也从 4 秒改成 2 秒，并在点击后 1.2 / 4 秒主动刷新。

### 手动更新

- 点左上角「更新状态」会等这次更新完成再返回
- 左下角会显示：正在更新 → 状态更新完成：部位 / 状态更新完成，没有变化 / 更新失败
- 右侧日志也会出现「状态更新」或「手动更新：没有变化」/「手动更新失败」
- 超过约 110 秒还没返回会显示超时，不会一直卡在「正在更新」
- 按钮在整个过程中是禁用的，完成后自动恢复

### 轮数怎么算

- 只有**正常聊天回复**才算一轮
- 互动走的是隐藏会话，**不算**普通聊天轮数
- 任意一次状态更新（互动、提到部位、按轮数、手动）都会把计数清零
- 同一条回复最多触发一次状态更新；提到部位优先于按轮数更新
- 例子：设置 5 轮更新一次，先正常聊 3 轮，再互动一次 → 互动更新后计数清零，接下来要再正常聊 5 轮才会触发下一次定时更新，不会在互动后马上又更新一次

## 坐标编辑

- 点左侧「设置」打开紧挨着身体状态列表的热区设置栏；左栏列表只读显示身体状态，编辑都在设置栏里做，完成/取消在设置栏右上角
- 按住热区范围直接拖动、叉叉删除、双击父级改名、拖拽树节点调整层级
- 多边形的顶点是粉色小点，拖顶点改形状；胶囊两端的小点用来改长度和方向
- 热区支持椭圆 / 胶囊 / 多边形，可复制、水平翻转
- 多预设：新建（可复制当前）/ 切换 / 删除 / 导入 / 导出
- 「重置热区」只把当前预设的热区恢复成 `default_positions.json`，不会动底图

## 预设导入导出

- 「导出」把当前预设的热区和底图打包成 JSON
  - 浏览器支持时弹「另存为」，可以自己选位置和文件名
  - 不支持时弹出目录输入框，填目标文件夹即可；文件会写到那个目录，路径显示在底部提示里
  - 出于安全考虑，导出目录只允许当前用户目录下（桌面、文档等）或插件数据目录；插件目录和系统目录会被拒绝
- 「导入」选择 JSON 后会新建一个预设并切换过去
- 每个预设可以有自己的底图：
  - 导入带图的预设会把图记在这个预设上
  - 页面「换底图」也会记到当前预设
  - 切换预设时：目标预设带底图就换上它的底图；没有底图就保持当前底图不变
- 导入不会覆盖已有预设，重名自动加序号

## 点击反馈

- 点击热区后，热区范围显示淡红色填充
- 连击次数越多颜色越深；连击结束后恢复无色
- 冷却中被拒绝的点击不会亮起

## 底图

- 「换底图」上传图片，自动压到最长边 2048px 的 WebP 再上传（上限 30MB）
- 「恢复默认」清掉当前预设的自定义底图，回到内置图

## 数据文件

运行时数据统一放在 `data/plugin_data/astrbot_plugin_body_monitor/`，不再写进插件目录：

- `positions.json`：坐标与预设（写入前留 `positions.json.bak`）
- `session.json`：最近一次收到消息的会话
- `settings.json`：页面右侧的设置（互动触碰词库、连击、体温基线、持续时间范围、每部位上限、导出目录等）
- `body_state.json`：每个预设各部位的温度、状态、剩余时间和严重度
- `images/custom.*`：当前自定义底图
- `images/presets/`：每个预设自己的底图
- `exports/`：默认导出目录（如果没有另外设置）

插件目录里只保留只读资源：`default_positions.json`（出厂地图）、`images/body.*`（内置底图）、`logo.png`（插件图标）。旧版本把数据放在插件目录里，升级/重载后会自动搬到 `data/plugin_data/astrbot_plugin_body_monitor/`。
- `logo.png`：插件列表里的图标（512×512，想换自己的图直接覆盖这个文件即可）

页面直链：`/api/v1/plugins/extensions/astrbot_plugin_body_monitor/ui`
（在 WebUI 里打开会自动带登录态；直接访问需要先登录面板）

## 常见问题

- **点热区没反应**：检查「触碰开关」、UMO 是否填对、是否在冷却中；看右下角日志的报错
- **角色不回复**：确认 AstrBot 的回复模型和会话正常；互动是隐藏消息，不会出现在聊天输入框
- **状态不更新**：检查「身体状态更新总开关」、状态更新模型、轮数设置；手动点「更新状态」看日志
- **状态更新很慢**：状态更新是回复后的第二次模型调用；给「状态更新使用的模型」单独选一个更快的模型，或缩短状态提示词
- **持续时间太短**：改「状态更新提示词」里的时长要求，或把状态设置里的「最短持续」调高；模型示例里的 duration 也要保持合理
- **手动更新一直转**：会等待结果并显示成功 / 没有变化 / 失败；超过约 110 秒会超时，不会一直卡住
- **换预设后状态不对**：身体状态按预设分开保存，切换预设会切换状态；底图则按预设独立保存
- **页面设置不生效**：确认点的是「完成」；状态设置的点「取消」会恢复打开前的值
